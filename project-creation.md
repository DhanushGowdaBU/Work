# NYBOSS Project Creation

This document defines how NYBOSS .NET projects are created.

The current stage creates the project skeleton and initial structural files.

The goal is to create:

- projects
- folders
- structural files
- project configuration
- project references
- solution entries

Business implementation is not part of this stage.

---

# Application Areas

NYBOSS server projects may be created under:

Apps/Business/

or:

Apps/Core/

The project structure depends on the selected application area.

---

# Target Framework

All newly generated projects must target:

net8.0

Use the framework explicitly when creating projects.

Do not allow the latest installed SDK/framework to determine the target framework automatically.

---

# Default Business Project

When the user requests a default Business project, create:

<ProjectName>.API
<ProjectName>.Common
<ProjectName>.Repository
<ProjectName>.Services

under:

Apps/Business/<ProjectName>/

---

# Business API Project

Create:

<ProjectName>.API

using the controller-based ASP.NET Core Web API template.

Use:

dotnet new webapi --framework net8.0 --use-controllers --name <ProjectName>.API

The API project must contain the required NYBOSS structure:

<ProjectName>.API/
├── Controllers/
├── Properties/
│   └── launchSettings.json
├── appsettings.json
├── appsettings.Development.json
├── appsettings.Local.json
├── build-info.json
├── <ProjectName>.API.csproj
└── Program.cs

The actual .NET template may generate additional files.

Remove:

<ProjectName>.API.http

unless explicitly requested by the user.

Do not replace or blank content generated by the .NET template.

Keep valid CLI-generated content in:

- Program.cs
- .csproj
- launchSettings.json
- appsettings files
- other required template-generated files

Create missing NYBOSS structural files where required.

Do not create business-specific controllers.

---

# Business Common Project

Create:

<ProjectName>.Common

using:

dotnet new classlib --framework net8.0 --name <ProjectName>.Common

The Common project must contain:

<ProjectName>.Common/
├── Constants/
│   └── <ProjectName>Constants.cs
├── Contracts/
│   ├── Repository/
│   │   └── I<ProjectName>Repository.cs
│   └── Services/
│       └── I<ProjectName>Service.cs
├── Models/
│   └── <ProjectName>Model.cs
├── Options/
│   └── <ProjectName>Options.cs
├── GlobalUsings.cs
└── <ProjectName>.Common.csproj

These files provide the initial Common project skeleton.

Do not implement business functionality.

Do not copy implementation from another application.

---

# Default Business References

Create:

<ProjectName>.API
    -> <ProjectName>.Services

<ProjectName>.Repository

dotnet add <project> reference <referenced-project>

# Core Domain Project

Create:

<ProjectName>.Domain

using:

dotnet new classlib --framework net8.0 --name <ProjectName>.Domain

The Domain project represents the domain layer of the Core application.

The Domain project must not be treated as identical to the Business Common project.

For the default Core structure, create:

<ProjectName>.Domain/
├── Models/
│   └── <ProjectName>Model.cs
├── Contracts/
│   ├── Repository/
│   │   └── I<ProjectName>Repository.cs
│   └── Services/
│       └── I<ProjectName>Service.cs
├── Constants/
│   └── <ProjectName>Constants.cs
├── Options/
│   └── <ProjectName>Options.cs
├── GlobalUsings.cs
└── <ProjectName>.Domain.csproj

These files are structural skeletons only.

Do not implement domain-specific business behavior unless explicitly requested.

Do not copy the contents of an existing Domain project.

If a similar Core project is requested, use the actual reference project's folder and file structure instead of assuming this default structure is identical to the reference.

# Domain and Common

Common and Domain are separate project types.

Business uses:

<ProjectName>.Common

Core uses:

<ProjectName>.Domain

Do not substitute one for the other unless explicitly requested.

A similar-project request must preserve whether the reference project uses Common or Domain.

---

# Explicit Project Composition

If the user specifies components, create only those components.

For Business:

"Create <ProjectName> with API, Common and Services"

creates:

<ProjectName>.API
<ProjectName>.Common
<ProjectName>.Services

under:

Apps/Business/<ProjectName>/

For Core:

"Create <ProjectName> with API, Domain and Services"

creates:

<ProjectName>.API
<ProjectName>.Domain
<ProjectName>.Services

under:

Apps/Core/<ProjectName>/

Do not create components that were not requested.

Only add references that are valid for the selected components.

---

# Similar Project

If the user requests:

"Create <ProjectName> similar to <ExistingProject>"

use the existing project as a structural reference only.

Determine:

- application area
- project composition
- project types
- project directories
- folders
- subfolders
- file names
- file locations
- project relationships

Then recreate the applicable structure using:

<ProjectName>.<Component>

under the appropriate application area.

---

# Similar Project File Rule

If the reference project contains:

<Folder>/<File>

create the corresponding folder and file in the new project.

Reproduce:

- file name
- file location
- extension

Do not copy the contents of the reference file.

If a .NET CLI template generates a corresponding file, retain the CLI-generated content.

If a file is created specifically as a structural placeholder, create minimal valid skeleton content.

---

# CLI-Generated File Content

When `dotnet new` creates a file, preserve its generated content.

Do not:

- empty it
- replace it with a placeholder
- recreate it unnecessarily
- copy content from another project

Only modify generated files when required for:

- target framework
- project references
- project naming
- required project configuration

---

# Structural File Content

Files created specifically to represent project structure should contain minimal valid skeleton code.

Examples:

<ProjectName>Model.cs
<ProjectName>Constants.cs
<ProjectName>Options.cs
I<ProjectName>Repository.cs
I<ProjectName>Service.cs
<ProjectName>Repository.cs
<ProjectName>Service.cs

Do not implement business functionality.

---

# Unwanted Template Files

The default API project must not contain:

<ProjectName>.API.http

If generated by the .NET Web API template, remove it.

Do not recreate it unless explicitly requested.

---

# Project Configuration

Generated `.csproj` files must:

- use the new project name
- target net8.0
- contain applicable project references
- contain only required configuration

Do not blindly copy an existing `.csproj`.

Do not copy unrelated package references.

Do not copy unrelated project references.

Keep valid content generated by the CLI.

---

# Solution

Use:

BNPP.NYBOSS.NextGen.Server.sln

Add every generated project using:

dotnet sln BNPP.NYBOSS.NextGen.Server.sln add <project-path>

Do not create a separate solution.

---

# Structure-Only Completion

Project creation is complete when:

- requested projects exist
- requested folders exist
- required structural files exist
- CLI-generated files retain their generated content
- unwanted template files are removed
- project names are correct
- project references are correct
- projects target net8.0
- projects are added to the existing solution

Do not continue into business implementation automatically.
